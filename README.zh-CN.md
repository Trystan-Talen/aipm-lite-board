# AIPM 轻量产研看板

基于 Scrumboy 改造，面向 **中文为主、1 名 AIPM（AI 产品经理）+ 4 名全栈开发**的小团队。保留 SQLite（嵌入式数据库）、看板、迭代、负责人、需求关系、API（应用程序接口）和 MCP（模型上下文协议），不引入重型部署依赖。

## 已配置的默认流程

| 阶段 | 使用方式 |
|---|---|
| 需求池 | 收集未经承诺的需求、客户反馈和产品想法 |
| 待澄清 | AIPM 补齐目标、边界、验收标准、优先级和依赖 |
| 开发中 | 开发已领取并开始实现 |
| 联调测试 | 联调、验收和缺陷回归 |
| 已完成 | 满足验收标准并可发布或已发布 |

默认优先级为：

- `P0｜立即处理`
- `P1｜当前迭代必须完成`
- `P2｜正常排期`
- `P3｜想法与优化`

新建需求时会自动填充中文模板：背景、用户问题、目标、非目标、验收标准、数据指标、风险与依赖。

## macOS 一键启动

双击项目根目录的 `启动AIPM看板.command`，或在终端执行：

```bash
./启动AIPM看板.command
```

脚本会：

1. 优先使用系统 Go（Go 语言工具链）；若没有，则下载到项目内的 `.tools/`；
2. 编译本地二进制；
3. 使用 `data/` 保存 SQLite 数据和上传文件；
4. 在 `http://127.0.0.1:8080` 启动并打开浏览器。

首次打开后，由团队负责人自行填写姓名、邮箱和密码完成初始化。密码不会写入仓库。

停止服务：在启动窗口按 `Control + C`。

## 推荐的 4 人开发规则

1. AIPM 只把验收标准明确的需求从“需求池”推进到“待澄清”。
2. 每个需求必须设置优先级；`P0` 仅用于线上阻断或严重数据风险。
3. 一个需求过大时，用父子任务拆成可独立验收的开发卡片。
4. 每名开发同时处于“开发中”的卡片建议不超过 2 张。
5. 卡片进入“联调测试”前，应补充自测结果、影响范围和回滚说明。
6. 只有满足验收标准后才能进入“已完成”。

## 数据与安全

- 默认仅监听本机 `127.0.0.1`，不会直接暴露到公网。
- 数据目录：`data/`。
- 团队正式使用前，应定期备份整个 `data/` 目录。
- 若要局域网访问、HTTPS（超文本传输安全协议）或 SSO（单点登录），请参考原项目 `README.md`。
